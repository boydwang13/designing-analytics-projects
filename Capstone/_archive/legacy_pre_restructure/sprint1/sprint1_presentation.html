一、Sprint 1 计划与目标 Sprint 1 Plan & Objectives (from PID)

时间范围：Weeks 1–2（双周迭代）。

Timeline: Weeks 1–2, aligned with the bi-weekly agile cadence.

核心目标：（1）在严格 GDPR 前提下生成可复现的大规模合成数据（节点属性 + 有向边 + 关系分数）；（2）完成探索性数据分析（EDA）与数据质量门禁；（3）建立基础网络拓扑可视化原型与可演示 Notebook，打通后续 ONA 管线。

Core goals: (1) Generate reproducible synthetic data (node attributes, directed edges, relational scores) under GDPR constraints; (2) Run EDA and a data-quality gate; (3) Deliver an initial topology prototype and a presentable notebook to establish the analytics pipeline for ONA.

计划内交付物（Definition of Done）：冻结 schema；nodes/edges CSV；问卷与 codebook 一致；DQ 报告；EDA 摘要；拓扑图（含 sandbox）；可复现 notebook；Sponsor 评审摘要。

Planned deliverables: Frozen schema; nodes/edges CSV; survey & codebook alignment; DQ report; EDA summaries; topology images (incl. sandbox); reproducible notebook; sponsor review pack.

与 PID 的差异说明：PID 曾提及 region；本项目以 GDPR 为准，跨群组差异由 Team / Seniority 等字段代理，不采集地理定位。

Note vs. PID wording: Where the PID mentions “region,” this sprint uses non-geographic proxies (e.g. Team, Seniority) for subgroup variation.

1) Schema 冻结与问卷 / 字典一致性

Rationale 依据与原理

ONA 要求“测量工具—数据表—指标定义”一致；否则中心性、孤立度无法审计。边表固定为：Hard/Soft 求助关系 + 频次权重 + 每条边上的 Awareness/Energy 关系属性（Cross & Parker 框架）。

ONA requires alignment among instrument, tables, and metric definitions. Edges are help-seeking ties (Hard/Soft) with frequency weights and per-edge Awareness_Score / Energy_Score as relational attributes.

Deliverables 产出
  • docs/mock_survey.md — Section I/J 与导出字段一致
  • docs/mock_codebook.md — 字段定义与 CSV 一致
Project value 对整体项目的支撑

为后续“可解释的管理名单”和合规叙事提供单一事实来源（single source of truth）。

Provides a single source of truth for explainable management lists and compliance narrative.

Sprint 2 衔接

可直接在同一 schema 上计算 In-degree / Out-degree / Betweenness 与 Isolation Score，无需返工改表。

Centrality and isolation metrics can be computed without schema rework.

2) 大规模合成数据生成（规则注入 + 随机扰动）

Rationale 依据与原理

PID 与 Sponsor 要求：在无真实通信数据下验证算法逻辑；通过注入 archetype（Hub / Broker / Island）+ 噪声，模拟“星型吸附、桥接、静默孤岛”等结构，便于场景注入测试。

Synthetic data with injected archetypes (hubs, brokers, islands) plus noise validates algorithms without production communications data and supports scenario-based testing.

Deliverables 产出
  • data/mock_data_nodes.csv（300 nodes）
  • data/mock_data_edges.csv（1042 edges）
  • scripts/generate_sprint1_assets.py
  • docs/data_generation_notes.md（seed、逻辑说明）
Project value 对整体项目的支撑

构成整个 capstone 的实证基础；同一管线可放大到更大 N 或调整参数做干预模拟。

Foundational dataset for the capstone; the same generator can scale or simulate interventions.

Sprint 2 衔接

作为 Sprint 2 的冻结输入快照，用于中心性、孤立分数与第一版“静默名单”。

Serves as the frozen input snapshot for Sprint 2 centrality, isolation scoring, and v1 silent lists.

3) 数据质量门禁（DQ Gate）

Rationale 依据与原理

网络指标对缺失值、非法枚举、重复 nomination rank 极敏感；在 Sprint 1 前置校验可避免 Sprint 2 出现“假阳性孤岛”或不可复现结果。

Graph metrics are sensitive to nulls, invalid enums, and duplicate ranks; early DQ prevents false isolation signals and irreproducible results in later sprints.

Deliverables 产出
  • outputs/dq_gate_report.md — PASS，0 issues
  • Notebook 内嵌快速 DQ cell
Project value 对整体项目的支撑

满足 Sponsor 对“可审计、可复现”的咨询级交付预期。

Supports consulting-grade, auditable, reproducible delivery.

Sprint 2 衔接

Sprint 2 每次改数据或阈值前可复用同一套规则做回归检查。

Same checks can be reused as regression tests before Sprint 2 data or threshold changes.

4) 探索性数据分析（EDA）

Rationale 依据与原理

在正式 ONA 指标前，需确认频次分布、类型结构、入/出度分布是否与业务叙事一致（例如是否存在明显中心节点与低出度尾部）。

Before formal ONA metrics, validate distributions and degree profiles against the intended business narrative (hubs vs. low-outdegree tail).

Deliverables 产出
  • outputs/eda_profile_v1.csv
  • outputs/sprint1_freq_type_distribution.csv
  • outputs/sprint1_node_degree_profile.csv
Project value 对整体项目的支撑

为管理层沟通提供“数据长什么样”的直观证据，并校准后续阈值设定。

Evidence for stakeholder communication and calibration of later thresholds.

Sprint 2 衔接

为 Isolation Score 分位数阈值、分层名单（非单一硬切）提供先验参考。

Informs quantile-based or tiered lists rather than a single hard cut in Sprint 2.

5) 网络拓扑原型（全量 + Sandbox）

Rationale 依据与原理

Sponsor 明确偏好敏捷：可先 20–50 节点“看得见”的静态原型再扩展。有向边 + 频次映射体现 Granovetter 意义上的强/弱连接强度；节点大小编码入度以突出 Hub。

Agile preference: a small sandbox first, then scale. Directed ties and frequency mapping reflect tie strength; node size encodes in-degree for hub visibility.

Deliverables 产出

  • outputs/sprint1_topology_sandbox.png — 子图演示
Project value 对整体项目的支撑

完成“从表到图”的管线证明，支撑 Sponsor 双周评审叙事。

Proves the table-to-graph pipeline and supports bi-weekly sponsor demos.

Sprint 2 衔接

Sprint 2 在同一图上叠加中心性着色、社区/团队分组、孤立风险标签。

Sprint 2 overlays centrality coloring, team grouping, and isolation-risk labels on the same visual layer.

Sprint 2 计划任务（中英对照）

#中文English
1 计算 In-degree / Out-degree / Betweenness centrality，并输出指标表。 Compute in-degree, out-degree, and betweenness centrality; export metric tables.
2 定义并实现 Isolation Score（含弱桥缺失惩罚等），设定阈值或分层规则，生成 Isolation_Risk_Flag。 Define isolation score (incl. weak-bridge deficit), set thresholds/tiers, derive Isolation_Risk_Flag.
3 输出第一版「静默团队/个人」管理名单（含解释字段与反指标提示）。 Deliver v1 management shortlist with explainability and counter-metric notes.
4 将指标层叠加到动态或迭代网络图上，形成第一轮管理评审材料。 Overlay metrics on network views for the first management review iteration.

风险控制：优先分层名单而非单一硬阈值；Sandbox 校验后再全量发布，降低误报。

Risk control: Prefer tiered lists over a single hard cut; validate on sandbox before full-network release.
